Section A

What it is

A GitHub Copilot–style inline autocomplete experience, purpose-built for Dockerfiles instead of general code — backed by a small transformer trained from scratch specifically on Dockerfile/IaC syntax, not a general-purpose LLM API.

Inline ghost text

Suggestions render inside real Dockerfiles via VS Code's native inline completion API — accept with Tab, keep typing to dismiss.

Runs 100% locally

No cloud account, no API key, no billing. The backend runs on your machine and the model never leaves it.

CPU-only inference

Served via ONNX Runtime. No GPU, no CUDA drivers, no quantization tricks needed at this model size.

Trained from scratch

Architecture, tokenizer, and training data chosen specifically for Dockerfile/IaC syntax — not fine-tuned from a general-purpose model.

Debounced & cancellable

Typing quickly doesn't pile up stale requests — a newer keystroke aborts the in-flight one for the previous.

Two ways to run

A Docker image for a reproducible environment, or a standalone executable — download and run, no dependencies.

Section B

How it works

Every keystroke in a Dockerfile follows the same short pipeline, entirely on localhost — from the debounced request in the editor to the ghost text that appears a fraction of a second later.

01 · EditorKeystroke pauses. Extension debounces for 300ms before asking for a completion.
→
02 · RequestPOST /complete with file content + cursor offset, sent to localhost:8123.
→
03 · ContextBackend takes the prefix before the cursor, caps it, tokenizes with GPT-2 BPE.
→
04 · InferenceONNX Runtime (CPU) runs the 80.8M-param model, generating up to 20 tokens.
→
05 · Ghost textCompletion returns to the extension and renders as inline suggestion. Tab accepts it.

Section D

Engineering decisions

A few choices that shaped this project, and the tradeoffs behind them.

Trained from scratch, not fine-tuned

Dockerfile/IaC syntax is narrow enough that an 80M-parameter model trained specifically on it can learn it well — and it removes any dependency on a pretrained base model's license, availability, or vocabulary.

ONNX Runtime for serving, not PyTorch

Decouples the deployed runtime from the training framework. The ONNX Runtime CPU execution provider ships without a PyTorch dependency in the Docker image or standalone binary, and is just as fast at this model size.

64-token window, not the full 256 trained

The model has no KV cache — it recomputes attention over the whole window on every generated token. Capping the deployed window well under the trained maximum trades some completion quality for latency that stays bounded and predictable.

Chunked, resumable training rounds

Pretraining ran across many Kaggle GPU sessions, each with a hard time limit. The training loop checkpoints after every round under one continuous learning-rate schedule, so a session ending mid-training never means restarting or losing the schedule's place.

Section F

Install manifest

Prerequisites: VS Code, and either Docker Desktop or the standalone Linux binary from the project's Releases page.

Start the backend

Pick one. Leave this terminal running — the extension needs it available the whole time you're using completions.

# Option A — Docker
docker pull sabisheak27/dockerfile-autocomplete:latest
docker run --rm -p 8123:8080 sabisheak27/dockerfile-autocomplete:latest

# Option B — standalone binary (download from Releases first)
chmod +x dockerfile-autocomplete-server
./dockerfile-autocomplete-server

Confirm it's running

In a second terminal. If this fails, stop and fix it first — nothing past this point works otherwise.

curl http://127.0.0.1:8123/health
→ {"status":"ready"}

Install the extension

Download dockerfile-autocomplete-0.1.0.vsix from the repo. In VS Code: Extensions view (Ctrl+Shift+X) → ··· menu → Install from VSIX.

Open or create a Dockerfile

Save a file as Dockerfile (no extension). Check the bottom-right status bar reads "Dockerfile" — not "Plain Text."

Use it

Pause briefly after typing — faint gray ghost text appears. Press Tab to accept, or keep typing to dismiss.

FROM python:3.11-slim

WORKDIR /app
RUN
No suggestions appearing?
  1. Is the backend terminal from step 1 still running, with no errors?
  2. Does curl http://127.0.0.1:8123/health still succeed?
  3. Is the file's language mode really "Dockerfile," not "Plain Text"?
  4. Check dockerfileAutocomplete.enabled is true (Ctrl+, → search "dockerfile autocomplete").
  5. Ctrl+Shift+U → dropdown → "Log (Extension Host)" for errors.
